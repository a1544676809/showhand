# 梭哈 · Five-Card Stud

一个完整可玩的**五张梭哈**（Five-Card Stud）网页游戏：2–5 人、洗牌发牌全流程、
筹码与边池系统、可证明公平的发牌，以及**按玩家视角导出文本局面**。
同一份代码也打包成 iOS App（Capacitor），可由 CI 在 macOS runner 上产出 `.ipa`。

React 19 + TypeScript + Vite。引擎是纯函数式的、可测试的，UI 只是它的投影。

```bash
npm install
npm run fetch:cards   # 下载公有领域扑克牌素材（Wikimedia Commons, CC0）
npm run dev           # http://127.0.0.1:5273
```

> 许可证：**GPL-3.0-only**，见 [LICENSE](LICENSE)。
> 牌面素材是 CC0（公有领域贡献），与 GPL 兼容，随仓库一并分发。

## 玩法规则（本作实现）

| 项目 | 说明 |
| --- | --- |
| 人数 | 2–5 人 |
| 牌堆 | 52 张（可选港式五张 28 张：8~A） |
| 底注 | 每人先投入底注 |
| 发牌 | 第一张**暗牌** + 第二张**明牌**；之后每轮各发一张明牌，共 5 张（一暗四明） |
| 下注 | 每发完一张明牌进行一轮下注，共 **4 轮** |
| 先手 | 每轮由**明牌最大者**先说话（明牌成对/三条者优先，同点数比花色） |
| 动作 | 弃牌 / 过牌 / 跟注 / 加注 / **梭哈（全下）** |
| 摊牌 | 五张牌比大小；只剩一人未弃牌则直接获胜，不亮底牌 |

### 牌型大小

```
同花顺 > 铁支(四条) > 葫芦 > 同花 > 顺子 > 三条 > 二对 > 对子 > 散牌
```

### 花色也分大小（关键差异）

与德州扑克不同，梭哈用花色作为**最终平局判定**：

```
♠ 黑桃 > ♥ 红桃 > ♣ 梅花 > ♦ 方块
```

先比点数，点数完全相同时比该张牌的花色。例如 `A♠ K♥ Q♦ J♣ 9♠` 与
`A♥ K♦ Q♣ J♠ 9♥` 点数完全相同，前者因黑桃 A 获胜。

因为花色参与比较，**两副不同的五张牌永远不会完全平局**，所以本作不会出现平分底池，
比较结果是一个严格的全序 —— 这一点在 `src/engine/evaluator.test.ts` 里有穷举验证。

## 主要功能

### 洗牌与发牌

- 发牌是**逐张**推进的状态机：`startHand → dealNextCard × n → 下注 → …`，UI 按节奏回放，
  所以能看到完整的发牌过程。
- 每轮发牌顺序：底牌与第一张明牌从庄家左手边开始；之后每轮从**当前明牌最大者**开始发。
- 每次进入新的明牌轮前自动销一张牌。
- 已弃牌的玩家不再发牌，全下玩家继续发满 5 张。

### 筹码系统

- 底注、跟注、加注（最小加注幅度 = 上一次加注幅度）、梭哈全下。
- **边池**：全下筹码不足时自动切分主池与边池，逐层判定归属。
- 无限注与有限注（固定注额 + 每轮加注封顶）两种模式。
- 一手结束自动结算、淘汰破产玩家、轮转庄家；只剩一人有筹码时整局结束。
- 引擎保证**筹码守恒**（`game.test.ts` 在每一手、每一步都断言总量不变）。

### 按玩家视角导出文本

顶栏 **「复制战况」** / **「完整局面」** 可以从任意座位（或观战者视角）导出当前牌局，
他人暗牌一律显示为 `★`，**不会泄露隐藏信息**。

**速览** —— 一行一位玩家，含牌型、下注、筹码，最适合直接贴给 AI 或群聊：

```
梭哈 第 1 手 · 第 1 轮下注 · 底池：40
视角：阿明（座位 0）

座位 玩家          筹码   本轮  累计  明牌   底牌  牌型             状态
──────────────────────────────────────────────────────────────────────
 0   阿明（你）     990     0    10   10♥   4♥   散牌·10 高       待行动 ←
 1   电脑·白鲨      990     0    10   6♣    ★    散牌·6 高（明牌）   —
 2   电脑·老K       990     0    10   9♥    ★    散牌·9 高（明牌）   —

轮到：阿明（你）   当前注额 0   需跟注 0   可加注到 20~990   全下 990
```

**完整** —— 完整的牌局报告，含行动记录与公正性信息：

```
══════════════════════════════════════════════════════
  梭哈 · FIVE-CARD STUD   第 3 手
  视角：阿明（座位 1）              阶段：第 2 轮下注
══════════════════════════════════════════════════════

▌牌局设置
  下注模式   无限注        底注 10
  注额单位   第1-2轮 20 / 第3-4轮 40     封顶 不限
  牌堆       52 张
  庄家座位   0（小李）

▌座位与筹码
  座位 0 小李          筹码     810  本手投入    60  明牌 9♥ 9♣   底牌 ★   跟注 20
  座位 1 阿明（你）    筹码     810  本手投入    60  明牌 K♠ 4♦   底牌 A♦   ← 轮到你
  座位 2 电脑·白鲨     筹码     950  本手投入     0  明牌 7♠       弃牌

▌底池
  主池 260
  合计 260

▌你的牌
  底牌 A♦（方块 A）
  明牌 K♠ 4♦
  当前牌型   散牌·K 高   [K♠ 4♦ A♦]
  还需 2 张牌才能成局

▌明牌强度对比
  1. 小李（你）  一对·9   [9♥ 9♣]
  2. 阿明        散牌·K 高 [K♠ 4♦]

▌行动信息
  当前注额 60  轮到 阿明（你）  需跟注 0
  可用动作：
    fold            弃牌
    check           过牌（无需投入）
    raise <amount>  加注到 120 ~ 880（总额，非增量）
    allin           全下 880

▌本手记录 …
▌洗牌公正性 …
```

**简洁**（4 行摘要）与 **JSON**（结构化，供程序消费）。四种格式都可一键复制或下载为文件。

文本排版做了 **CJK 宽字符对齐**处理，中文与等宽字符混排时表格不会错位 ——
`renderSummaryText` 有专门的测试断言表头的 `─` 分隔线与表头等宽、且每一行列数一致。

### 界面

- **自适应、不翻页**：外壳固定为一个视口高（`100dvh`），整页**永不滚动**；只有日志面板和
  弹窗内部滚动，所以牌桌和下注按钮始终在屏幕上，快捷键提示放在下注栏**上方**，
  让下注栏贴住屏幕底部。座位以**内侧边缘为锚点**（上半圈从锚点向下长、下半圈向上长），
  所以手里握着五张牌也不会顶到顶栏或下注栏。
  牌桌按容器的宽高**求解出恰好填满的长宽比**（夹在 0.85–1.62 之间），所以 16:9、
  **iPad 的 4:3（横竖屏都算）**、手机的 9:19.5 都不会留下大片空白 —— 早期按断点写死比例时，
  竖屏 iPad 会白白浪费约 300px 高度。牌面随桌子等比缩放。
  触摸设备（`pointer: coarse`）上按钮与滑杆会自动放大到可点尺寸。
  `npm run shots` 会在 1680×1050、1366×768、1366×1024、1024×768、810×1080、430×900、
  350×1127 等视口断言页面无溢出，并断言**所有座位都不越界到顶栏/下注栏**。
- **亮色 / 暗色模式**：所有颜色都是语义化 CSS 变量，一套变量切换整站配色。
  首次访问跟随系统 `prefers-color-scheme`，之后记住手动选择。
- **按宽度收敛的顶栏**：窄屏下按钮只留图标（复制战况 / 记录 / 公正性 / 规则 / 重开 / 主题），
  重复入口自动隐藏，日志改为抽屉，保证一行放得下。
- **上帝视角逐张推进**：进入上帝视角会自动切到「手动」节奏，底牌不会自己翻开 ——
  底部显示 `下一步 发底牌 → 四号位` 与 **「翻出下一张 ▸」** 按钮，点一下引擎前进一步
  （发一张牌 / 让一个 AI 行动 / 开牌结算），快捷键 <kbd>Enter</kbd>。
  想让它自动跑，切回「正常 / 快 / 极快」即可。
- **代打（导演下注）**：上帝视角下，轮到谁就把完整的下注面板交给操作者 ——
  底栏出现 `代 三号位 行动` 的金色标签，该座位名牌上挂一个 `代打` 角标，
  弃牌 / 过牌 / 跟注 / **加注滑杆与 ½池·⅔池·1池·全下 预设** / 梭哈 全部可用，
  下注记在那个玩家名下。AI 座位同样可以代打，随时接管。
- **座位控制**：顶栏的 🎛 按钮控制每个座位旁边那排小按钮是否显示。每个座位有三个：

  | 按钮 | 作用 |
  | --- | --- |
  | 🤖 / 🧑 | 在 AI 控制与真人控制之间切换。两种模式因此可以随时互相转换 |
  | 👁 / 🙈 | 观看 / 隐藏该玩家的底牌。**底牌在上帝视角下也默认隐藏**，必须手动点开 |
  | 📋 | **直接复制**该玩家视角的局面到剪贴板（对家底牌隐藏），弹出提示条确认；不打开窗口 |

  只有顶栏的「复制战况」会打开导出窗口 —— 座位上的 📋 是纯复制，不打断操作。

- **上帝视角不再等于「全部亮牌」**：它只是「所有座位初始为 AI、无遮挡页、手动推进」。
  底牌始终是关着的（**包括自己正前方那个座位**），看谁的牌就点谁旁边的 👁，
  再点一下重新盖上。

### 玩家标识符与筹码记录

座位表里每个位置都可以填一个**标识符**（独立于昵称）。

- **填了标识符** —— 该玩家的筹码会记录在本机（`localStorage`），下次填同一个标识符时
  自动读回，重启浏览器也不会丢；也可以给每个座位单独设定筹码（标识符命中记录时会自动带出，
  仍可手动改写）。
- **没填标识符** —— 该座位既不读取也不写入任何记录，退回到原来的行为，照样能正常开局。

开局后每手结算都会把筹码写回记录，`重新开始` 时以记录里的筹码为准继续。
设置界面底部可以一键清除全部记录。


### 可证明公平的发牌（Provably Fair）

1. 每手开始前公布 `SHA-256(serverSeed)` 作为**承诺**。
2. 随机种子为 `SHA-256(serverSeed:clientSeed)`，用 SHA-256 计数器模式驱动
   **无偏** Fisher–Yates 洗牌（拒绝采样，无取模偏差）。
3. 本手结束后公布 `serverSeed`，任何人都能复现整副牌序。

界面里的「公正性」面板会**当场重新计算**牌序并与实际发牌比对，给出通过/失败结论。

### 两种模式 + 座位控制

模式的差别只在**初始值**，开局后靠座位控制按钮随时混搭：

| | 同屏轮流 | 上帝视角 |
| --- | --- | --- |
| 座位初始 | 全部真人 | 全部 AI |
| 遮挡页 | 开（防止同设备偷看） | 关 |
| 底牌 | 轮到谁，谁自己看 | 默认全关，用 👁 逐个点开 |
| 节奏 | 正常自动 | 手动逐张 |

**每个座位由真人还是 AI 控制，在设置界面就能逐个定好** —— 座位表最右的「控制」列，
点一下在 🤖 AI 与 🧑 真人之间切换，不用先进牌局再改。开局后同一件事由座位旁边的
🤖/🧑 按钮完成，两个模式由此无缝互通，中途改变也不需要重开牌局。

顶栏的 **重新开始** 与 **离开** 是分开的：

- **重新开始** —— 原地重开，保留座位、设置与筹码记录，开始新的一局；
  顶栏的「第 N 局 · M 手」会记下这是连续第几局。
- **离开** —— 回到设置界面，所有输入都保留着，改完再开。

AI 有五种性格（紧凶 / 松凶 / 稳健 / 跟注站 / 赌徒），决策由牌力评估 + 底池赔率 + 对手明牌强度
推导，并带少量随机性；决策种子来自本手洗牌承诺，因此**整局可复现**。

## 项目结构

```
src/
  engine/            纯 TypeScript 引擎，零 UI 依赖
    types.ts         领域模型（牌、牌型、玩家、状态、动作）
    sha256.ts        自带 SHA-256（同步，便于复现；对 NIST 向量有测试）
    rng.ts           确定性随机源 + 无偏取整 + Fisher–Yates
    cards.ts         牌表示、记法解析、洗牌与承诺
    evaluator.ts     1–5 张牌的梭哈牌型评估与全序比较
    pots.ts          边池切分与派彩
    game.ts          状态机：发牌 / 下注 / 全下 / 摊牌 / 结算 / 单步描述
    text.ts          按视角的速览、完整、简洁、JSON 导出
    ai.ts            机器人决策
  ui/
    useGameController.ts  对局生命周期、自动/手动节奏、视角与遮挡页、座位控制
    bankroll.ts           按标识符持久化筹码（localStorage）
    layout.ts             尺寸测量与牌桌几何（宽高双向约束、碰撞求解、响应式比例）
    theme.ts              亮/暗主题，跟随系统 + 本地记忆
    quickstart.ts         分享链接解析
    Table / ActionBar / panels / SetupScreen / PlayingCard
  styles.css         全部样式（语义化 CSS 变量，暗色为默认）
scripts/
  fetch-cards.ps1    下载 CC0 牌面素材（走本地代理、校验内容、429 退避）
  screenshot.mjs     用 CDP 驱动无头 Chrome：截图 + 布局/DOM 不变量断言
```

引擎不依赖 React、不依赖浏览器，`npm test` 全部在 Node 下运行。

### 测试覆盖

引擎有 **175 个测试**，重点覆盖容易出错的地方：

- SHA-256 对 NIST/FIPS-180-4 向量，并与 `node:crypto` 交叉验证。
- 洗牌：牌序可复现、是无重复排列、**卡方检验**证明位置均匀（拒绝有偏洗牌）。
- 无偏取整 `nextBelow` 的边界与分布。
- 牌型：全部 9 种牌型、A2345 当顺子、AKQJ10 不绕回、花色平局判定、
  两两组合穷举确认**不存在平局**。
- 牌型（性质测试）：**穷举全部 294,203 种 1–4 张的部分手牌**，确保任意明牌组合
  都能被安全评估 —— 这条测试抓到了「明牌四张同点、没有带牌」时评估器崩溃的真实 bug。
- 边池：等额、全下不足、两个全下层级、弃牌玩家的死钱、无法争夺的层回落。
- 状态机：2–5 人、发牌张数与顺序、销牌、先手判定、加注后重新响应、加注封顶、
  弃牌直接获胜、真实边池端到端、破产结束、**25 手混合策略下的筹码守恒**。
- 文本导出：**逐座位验证他人暗牌不出现在输出中**、摊牌后可见、JSON 结构合法、
  「速览」表头与 `─` 分隔线等宽且每行列数一致。
- AI：永远只返回合法动作、可复现、好牌会下注、烂牌面对大注会弃牌、
  上千手自对弈不产生非法状态。
- 筹码记录：只写填了标识符的座位、匿名座位完全不落盘、记录未变时不写存储、
  损坏的存档不会崩、无 `localStorage` 时静默降级。
- 牌桌几何：多种视口 × 2–5 人下**穷举断言所有手牌框互不相交**、牌面不越出桌框、
  牌面尺寸永不退化；小到 360px 手机 + 4 人时求解器会退化到最小牌面而不是重叠。
- 界面（`npm run shots`，在真实 Chrome 里跑）：七种视口下**页面无纵向溢出**、
  上帝视角**底牌默认全部隐藏（含自己正前方那个座位）**、点 👁 只翻开目标座位且再点一次
  重新盖上、AI/真人切换可逆、**代打面板标注的座位与实际行动座位一致且下注被引擎接受**、
  牌面不重复、暗牌背后不存在牌面 img 节点（遮挡在 DOM 层也成立）、**任何座位都不得越界到顶栏或下注栏**。

## iOS / .ipa

同一份代码用 **Capacitor** 包成 iOS App：整个游戏跑在 WKWebView 里，引擎、AI、
可证明公平洗牌、筹码记录全部离线可用，牌面素材也一并打进包里。

**为什么走 CI**：iOS 只能在 macOS 上用 Xcode 编译，这台机器是 Windows。
`.github/workflows/ios.yml` 在 `macos-15` runner 上构建，产出可直接下载的 `.ipa`。

```bash
# 触发一次构建（也可以直接 push 到 main）
gh workflow run "iOS IPA"

# 等它跑完并取回产物
gh run watch $(gh run list --workflow="iOS IPA" --limit 1 --json databaseId --jq '.[0].databaseId')
gh run download $(gh run list --workflow="iOS IPA" --limit 1 --json databaseId --jq '.[0].databaseId')
```

产物是 **未签名** 的 `Showhand-unsigned.ipa`（约 5.7 MB）：

| 内容 | 大小 |

### 安装

未签名意味着不能直接双击装进 iPhone —— 需要重新签名或越狱环境：

- **Sideloadly / AltStore / SideStore** —— 用你自己的 Apple ID 重签，免费账号 7 天有效，
  到期重签即可。这是最常用的方式。
- **TrollStore** —— 支持的 iOS 版本上可以直接安装未签名 IPA，永久有效。
- **越狱设备** —— 直接装。
- 想做成正式分发版本，需要 Apple Developer 证书，把 `xcodebuild` 的签名参数换成
  你自己的 `CODE_SIGN_IDENTITY` / `PROVISIONING_PROFILE_SPECIFIER` 即可。

### iOS 侧做了什么

- `capacitor.config.ts` —— `contentInset: 'never'`，布局完全交给 CSS 的 `100dvh`；
  `styles.css` 用 `env(safe-area-inset-*)` 避开刘海与 Home 指示条。
- 窄屏输入框字号设为 16px，避免 iOS 聚焦时自动放大页面。
- `Info.plist` —— 桌面名称 `梭哈`、`arm64`、`ITSAppUsesNonExemptEncryption = false`、
  浅色状态栏。
- `assets/icon.svg` / `assets/splash.svg` 用无头 Chrome 渲染成 PNG
  （`scripts/make-icons.mjs`），不需要任何图形工具链。

> Capacitor 模板会把同一张 2732×2732 启动图当作 1x/2x/3x 塞三份（5.4 MB 完全相同的像素）。
> 这里改成单尺度 imageset + 2048×2048 一张，配合关掉 sourcemap，`.ipa` 从 9.1 MB 降到 5.7 MB。

## 牌面素材

来自 Wikimedia Commons 的
[Category:Public domain playing cards](https://commons.wikimedia.org/wiki/Category:Public_domain_playing_cards)，
共 52 张牌面 + 1 张牌背，全部为 **CC0（公有领域贡献）**。

`npm run fetch:cards` 会把它们下载到 `public/cards/<CODE>.png`，并写出
`public/cards/manifest.json`，记录每张图的原始文件页、作者与许可证。
素材文件本身**未提交进仓库**，用脚本获取。

脚本有几个刻意为之的地方：

- **下载缩略图而不是原图。** Wikimedia 对直接抓取原始文件返回
  `429 Too many requests`（附 `Retry-After: 600`），并明确要求客户端改用缩略图服务。
  缩略图走 `thumb.wikimedia.org` 的 CDN，不受限流影响 —— 换成缩略图后 53 个文件
  一次全部成功。
- **逐个下载，不并发。** 两三个并发请求就会触发 429。
- **按 magic bytes 校验。** curl 在 HTTP 错误时会老老实实把错误页写进输出文件，
  所以每个文件都必须以 PNG 签名开头，否则删掉重试。

> 本机直连 `upload.wikimedia.org` 不通，脚本默认走本地代理 `socks5h://127.0.0.1:10808`，
> 可用 `-Proxy ''` 直连、`-Force` 强制重下。

如果素材尚未下载或加载失败，`PlayingCard` 会退化为内置的排版式牌面，游戏依然完整可玩。

## 已知取舍

- 花色参与比较是**港式/中文梭哈**的通行规则，也与本作「两副牌不会平局」的设计一致。
  如果想改成德州扑克式的花色无关，只需调整 `evaluator.ts` 的 `suits` 数组。
- 明牌先手规则采用标准 stud 的「明牌成手最大者先说话」；部分简易实现只比最大单张。
- 摊牌时亮出所有未弃牌玩家的底牌（多数线上实现的做法），而非只亮最后加注者。
- 同屏模式依赖「遮挡页 + 自觉」，无法在技术上阻止同一设备上的其他人偷看。
- iOS 状态栏固定为浅色文字，配合默认的暗色主题；在 App 内切到亮色主题时状态栏对比度偏低
  （要随主题切换需要引入 `@capacitor/status-bar`）。
